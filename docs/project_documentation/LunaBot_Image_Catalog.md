## Requested visual evidence not found

Repository includes RViz configurations and model/world source, an SDF-informed diagram, and 2026-11-19 GUI evidence with two complete manual mission gate passes. The retained run folders contain logs, map rasters and status snapshots, but a direct search found no captured Gazebo/RViz screenshot files for rover front/side/top, terrain/habitat GUI, sensor placement, live scan, semantic/cost map display, TF tree, obstacle replanning or mission completion. Do not pass the schematic or occupancy grids off as rover screenshots.

## Capture instructions to generate missing evidence

1. On the intended demonstration workstation, start the GUI acceptance profile from repository root:

   ```bash
   source /opt/ros/humble/setup.bash
   WSL_SOFTWARE_PROFILE=1 FINAL_DEMO=1 AUTO_GOAL=false EVIDENCE=1 bash ./launch-l
   ```

2. Wait until `/map`, `/lunabot/lidar/scan`, `/lunabot/terrain/plan`, `/lunabot/obstacles/map` and mission state are fresh. Select `Set Goal` in RViz and record an actual mission through obstacle replan and goal completion. Recent 2026-11-19 complete gate runs are `evidence/runs/20261119-164616-phase-l-view-4738/` and `evidence/runs/20261119-171329-phase-l-view-6711/`; they contain maps and logs, but no screen captures.
3. Capture unaltered desktop images: `gazebo_lunar_environment.png`, `rover_front_view.png`, `rover_side_view.png`, `rover_top_view.png`, `rviz_tf_robotmodel.png`, `rviz_lidar_map.png`, `rviz_semantic_layers.png`, `rviz_costmap_path.png`, `rviz_obstacle_replan.png`, and `mission_completed.png`. Include visible app UI/timestamp or accompany with run ID and source logs. Copy originals into this `assets/` folder and update captions with run path, display configuration and evidence scope.
4. If GUI is unavailable, retain headless map/log artifacts and mark the GUI screenshot requirements not captured. A generated visualization of an occupancy raster is still not a Gazebo/RViz screenshot.
